# Путеводитель по проекту

Этот документ помогает продолжить работу с текущего состояния. Источником истины остаются исходный код и тесты: правила и уровни могут меняться.

## Где что находится

| Часть игры                                | Исходники                                                                                               |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Меню, карта глав и выбор уровня           | `src/`                                                                                                  |
| Порядок уровней и отображаемые номера     | `src/levels.ts`                                                                                         |
| Сохранения и постоянные ID уровней        | `src/progress.ts`                                                                                       |
| Подсказки, предохранители и звёзды        | `src/hints.ts`                                                                                          |
| Схемы уровней и игровые правила           | `resources/references/ui-review/glass-chapter-one.js`, `glass-underground.js`, `glass-energy.js`        |
| Общая страница уровня, рисунки и обучение | `resources/references/ui-review/glass-level.template.html`, `glass-hatch-art.js`, `glass-onboarding.js` |
| Сборка страниц уровней                    | `resources/references/ui-review/build-glass.mjs`                                                        |
| Учёт ресурсов и проверка публикации       | `resources/manifest.json`, `resources/production-files.json`, `scripts/`                                |

В первой главе **25 игровых уровней**. Их видимые номера задают порядок в меню, а постоянные ID служат адресами страниц и ключами сохранений. Например, бывший ID `35` выведен из игры, но его история остаётся в сохранении. При перестановке или замене уровня не переиспользуйте ID и проверяйте переход на следующий уровень.

`public/levels/` и `glass-level.html` создаются сборкой. Меняйте исходники, затем запускайте `npm run level:build`; ручные правки созданных страниц исчезнут. Для выпуска собирайте `dist/` через `npm run build`.

## Важные правила игры

- Обрыв ограничивает оставшееся время **30% от начального таймера**: если осталось меньше, время не меняется. Обрыв не возвращает заряд. См. `glassOutageRemainingMs` в `glass-energy.js`.
- Крестовина проводит ток по двум изолированным каналам. Реле открывает боковые заслонки после первого прохода и удерживает их до прохождения второго канала; новая попытка сбрасывает заслонки.
- Парные подземные люки на уровнях 19–22 — неподвижные выходы. Поворачиваются окружающие трубы. В 23-м уровне появляется труба на салазках.
- Заряд, звёзды, предохранители и подсказки связаны с сохранённым профилем. Не сбрасывайте профиль ради проверки новой схемы; используйте отдельное хранилище браузера.

## Как прорабатывать уровень

Сложность должна расти за счёт честных развилок и дополнительных действий. Проверяйте маршрут **от трансформатора и от дома**: очевидное начало с любой стороны не должно сразу выдавать всю схему. Ложный путь должен быть правдоподобным, но полное решение и все предусмотренные звёзды — достижимыми. Сверяйте реальные повороты, прохождение реле, люков, обрыва и таймер, а не только рисунок готового маршрута.

Обучающие облачка пишите коротко, обычно не длиннее двух строк на телефоне. У механики должен быть понятный зрительный отклик: состояние заслонок, обрыв, сгорание предохранителя и выбор кнопок нельзя показывать только текстом. Для изменений интерфейса проверяйте настольный экран и телефон **390 × 844**; для сложного взаимодействия проходите уровень в браузере от начала до результата.

## Проверка изменений

```bash
npm ci
npm run build
npm run check:quick
```

Эти же проверки запускаются в GitHub Actions при отправке изменений и pull request. Для адресной отладки доступны `npm test`, `npm run level:check`, `npm run typecheck` и `npm run release:check`. Перед сдачей убедитесь, что сгенерированные страницы актуальны и в коммит попали только нужные файлы. Для проверки на телефоне используйте `npm run phone`; работающий сервер и публичный туннель не требуют перезапуска после обычной правки файлов.
